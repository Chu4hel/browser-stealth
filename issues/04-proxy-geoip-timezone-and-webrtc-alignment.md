# Issue 04: Автоматическая синхронизация сетевой гео-таймзоны прокси с WebRTC и Intl API

## Описание
При использовании резидентных или мобильных прокси трафик идет через удаленный IP-адрес (например, США, Германия, Япония), в то время как системное время машины автоматизатора, часовой пояс движка V8 и локаль JavaScript могут оставаться хостовыми (например, `Europe/Moscow`, MSK UTC+3).

## Уязвимость для антифрод-систем (Cloudflare, DataDome, Akamai)
1. **Несовпадение GeoIP таймзоны и браузерной таймзоны:**
   - WAF определяет страну и регион по IP (например, `America/New_York`, UTC-5).
   - Скрипт защиты выполняет:
     ```javascript
     const browserTz = Intl.DateTimeFormat().resolvedOptions().timeZone;
     const offset = new Date().getTimezoneOffset();
     ```
   - Если IP из Нью-Йорка, а `browserTz` возвращает `Europe/Moscow` или `offset` не совпадает с зоной IP, сессия моментально получает высокий риск фрода (Fraud Score > 90).
2. **Утечка реального локального и внешнего IP через WebRTC:**
   - При активном WebRTC браузер может отправлять STUN-запросы в обход SOCKS5/HTTP-прокси, раскрывая реальный публичный IP машины или внутренний IP локальной подсети (`192.168.x.x`).

## Требуемые изменения
1. **Автоматический резолв таймзоны по прокси:**
   - В модуле `proxy/` при инициализации прокси определять целевую таймзону (IANA Timezone, например `America/New_York`) и передавать ее в конфигурацию профиля.
   - Использовать нативный CDP-метод `Emulation.setTimezoneOverride(timezoneId=...)` для полной консистентности системных часов движка V8.
2. **Синхронизация локали с регионом:**
   - Автоматически синхронизировать язык `Accept-Language` и `navigator.languages` со страной прокси.
3. **Строгая изоляция WebRTC:**
   - Убедиться, что WebRTC использует политику `default_public_interface_only` или `disable_non_proxied_udp`, исключая любые утечки маршрутов вне туннеля прокси.
4. **Тестирование:**
   - Добавить тесты на проверку синхронизации таймзоны при заданном прокси.
